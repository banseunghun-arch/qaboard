# QANOW Design Brief

**프로젝트**: QANOW 질의응답 게시판  
**버전**: 1.0.0  
**목적**: 회원이 상품 관련 질문을 하고, 관리자가 답변하는 Q&A 커뮤니티 플랫폼  
**대상**: 전자상거래 고객 및 관리자  
**작성일**: 2025-08-29

---

## 1. 프로젝트 & 사용자 요약

### 프로젝트 개요
QANOW는 회원이 질문을 올리고 관리자가 답변하는 신뢰할 수 있는 Q&A 플랫폼입니다. 
- **회원**: 상품 구매 전 궁금한 점을 질문하고, 관리자 답변을 확인
- **관리자**: 미답변 질문을 찾아 신속하게 답변 작성 및 관리
- **목표**: 고객 신뢰 구축, 효율적인 소통

### 핵심 가치
- 빠르고 신뢰할 수 있는 답변
- 투명한 질문-답변 과정
- 회원과 관리자의 명확한 역할 분리

---

## 2. 디자인 목표

1. **첫인상 강화**: 메인 페이지에서 QANOW의 가치를 명확하게 전달
2. **작업 효율성**: 관리자가 빠르게 질문을 찾고 답변할 수 있는 UI
3. **신뢰감**: 안정적이고 전문적인 인상으로 브랜드 신뢰도 상향
4. **접근성**: 모든 사용자가 쉽게 질문하고 답변을 확인
5. **성능 우선**: LCP < 2.5초 달성, 불필요한 시각 효과 제거
6. **일관성**: 회원과 관리자 모두 통일된 디자인 언어 경험

---

## 3. 브랜드 키워드

- **신뢰감** (Trustworthy): 안정적이고 투명한 소통
- **현대적** (Modern): 과도하지 않은 미니멀 디자인
- **효율** (Efficient): 빠른 네비게이션과 직관적 작업
- **명확성** (Clarity): 상태와 액션이 명확하게 보임
- **정돈됨** (Organized): 정보가 체계적으로 배열

---

## 4. 핵심 화면 3개의 목적

### Screen 1: 메인 페이지
**목적**: QANOW가 무엇이고 어떻게 사용하는지 30초 내에 이해시키기
- 서비스 소개 (한 문장)
- 이용 흐름 시각화 (질문 → 확인 → 답변)
- 가치 제안 (3-4개)
- CTA: "지금 질문하기" (회원가입/로그인)

### Screen 2: 질문 리스트 페이지
**목적**: 회원과 관리자가 질문을 효율적으로 조회하고 액션 취하기
- 회원: 자신의 질문 + 상태 확인
- 관리자: 전체 질문 + 필터 ("답변 필요" / "답변 완료")
- 목표: 원하는 질문을 3초 내에 찾기

### Screen 3: 질문 상세 페이지
**목적**: 질문 내용 확인 및 (회원) 또는 답변 작성/수정 (관리자)
- 회원: 질문 상세 + 관리자 답변 확인 + 수정/삭제 (답변 전)
- 관리자: 질문 상세 + 답변 폼 + 질문 삭제 버튼
- 목표: 핵심 정보를 명확하게 표시, 폼 입력이 편리하게

## 5. 화면별 정보 우선순위

### 메인 페이지
1. **Hero (최상단)**: 한 문장 서비스 소개 + CTA "지금 질문하기"
2. **이용 흐름**: 3단계 시각 (질문 작성 → 관리자 확인 → 답변 받기)
3. **가치 제안**: "빠른 답변", "신뢰할 수 있는 정보", "전문가 관리" 등
4. **헤더/푸터**: 로고, 네비게이션, 링크

### 질문 리스트 페이지
1. **필터 바** (관리자): "전체", "답변 필요", "답변 완료"
2. **질문 카드**: 제목, 작성자(관리자용), 작성일, 상태(텍스트+색상)
3. **"더보기" 버튼**: 초기 20개 후 추가 로드
4. **헤더**: "내 질문" / "질문 목록", "새 질문 작성" CTA
5. **빈 화면**: "아직 질문이 없습니다" + CTA

### 질문 상세 페이지
1. **제목**: 명확하고 읽기 쉬운 폰트 크기
2. **상태 배지**: "답변 대기 중" / "답변 완료" (텍스트+색상)
3. **질문 내용**: 여백 충분히, 한눈에 읽을 수 있는 길이
4. **관리자 답변** (조건부): 답변이 있으면 강조된 섹션으로
5. **폼** (회원 수정 / 관리자 답변): 입력창이 명확하고 저장 버튼 눈에 띄게

- 필터 바 (관리자만)

- 질문 내용
- 액션 버튼 (수정/삭제-회원 또는 삭제-관리자)

- 폼 (질문 수정 또는 답변 작성)

## 8. 회원과 관리자 상태 차이

### 질문 리스트 페이지

**회원이 보는 것**:
- 자신의 질문만 표시
- 필터 없음
- 액션: 질문 클릭 → 상세 페이지

**관리자가 보는 것**:
- 모든 회원의 질문 표시 (작성자명 표시)
- 필터: "전체", "답변 필요", "답변 완료"
- 액션: 질문 클릭 → 상세 페이지

### 질문 상세 페이지

**회원이 보는 것**:
- 자신의 질문만 접근 가능
- 상태: "답변 대기 중" (수정/삭제 가능) 또는 "답변 완료" (읽기만)
- 답변: 관리자 답변이 있으면 강조된 섹션으로 표시
- 액션: 수정 / 삭제 (답변 전), 답변 확인 (답변 후)

**관리자가 보는 것**:
- 모든 질문 접근 가능
- 질문 작성자명 표시
- 상태: 구분 없음 (모든 상태 접근)
- 답변: 답변 폼 또는 기존 답변 수정
- 액션: 답변 작성 / 수정 / 질문 삭제 (부적절한 질문 제거)

## 9. 페이지 간 이동 구조

```
메인 페이지
├─ "지금 질문하기" → 로그인/회원가입 → 질문 리스트 또는 질문 작성
├─ "회원가입" → 회원가입 폼 → 메인
└─ "로그인" → 로그인 폼 → 메인

질문 리스트 페이지 (회원)
├─ "새 질문 작성" → 질문 작성 폼
├─ 질문 카드 클릭 → 질문 상세 페이지
├─ "더보기" → 목록에 20개 항목 추가
└─ "로그아웃" → 로그인 페이지

질문 리스트 페이지 (관리자)
├─ "질문 목록" 필터 클릭 → 상태별 필터링
├─ 질문 카드 클릭 → 질문 상세 페이지
├─ "더보기" → 목록에 20개 항목 추가
└─ "로그아웃" → 로그인 페이지

질문 상세 페이지
├─ "수정" → 질문 수정 폼
├─ "삭제" → 삭제 확인 → 리스트로 이동
├─ "답변 작성" (관리자) → 답변 폼
├─ "내 질문으로" 또는 "질문 목록으로" → 리스트 페이지로 이동
└─ "로그아웃" → 로그인 페이지
```

## 11. 색상 역할

### Primary Color: 어두운 네이비 & 블루
- **용도**: 헤더, 주요 버튼, 활성 상태
- **RGB**: 약 #1a237e (깊은 네이비) ~ #0d47a1 (짙은 블루)
- **의미**: 신뢰감, 전문성, 안정성

### Accent Color: 바이올렛 & 퍼플
- **용도**: 강조 요소, 호버 상태, 특정 액션
- **RGB**: 약 #7c4dff (밝은 바이올렛) ~ #512da8 (진한 퍼플)
- **의미**: 창의성, 프리미엄 느낌

- **대기**: 주황색 (#ff9800) - "답변 대기 중"
- **완료**: 초록색 (#4caf50) - "답변 완료"

## 13. 간격과 레이아웃 방향

### 기본 간격 단위 (Spacing Scale)
- **4px**: 최소 간격 (요소 내부)
- **8px**: 컴포넌트 간 최소 간격
- **16px**: 섹션 내 요소 간 기본 간격
- **24px**: 섹션 간 간격
- **32px**: 주요 섹션 간 간격
- **48px**: 페이지 최상단/최하단 여백

### 레이아웃 원칙
- **최대 너비**: 1200px (데스크톱) - 너무 넓지 않게
- **좌우 여백**: 데스크톱 48px, 태블릿 32px, 모바일 16px
- **가운데 정렬**: 콘텐츠는 중앙 정렬, 시각 복잡도 감소
- **카드 간격**: 16px (목록에서)

### 반응형 기준
- **데스크톱**: 1024px 이상 (네비게이션 상단 고정)
- **태블릿**: 768px - 1023px (레이아웃 조정 가능)
- **모바일**: 375px - 767px (단일 컬럼, 터치 타겟 44px 이상)

## 14. 버튼·입력창·카드·배지 규칙

### 버튼
**Primary Button** ("지금 질문하기", "저장")
- 배경: 어두운 네이비 또는 바이올렛
- 색상: 흰색
- 높이: 데스크톱 44px, 모바일 48px
- 모서리: 6-8px (완전히 둥글지 않게)
- 호버: 색상 어두워짐 (밝아지지 않음)
- 비활성: 회색으로 변경

**Secondary Button** ("취소", "목록으로")
- 배경: 투명 또는 연한 회색
- 테두리: 1px 회색
- 높이: Primary와 동일
- 호버: 배경 어두워짐

### 입력창
- 높이: 44px 텍스트 입력, 텍스트에어리어는 최소 100px
- 테두리: 1px #e0e0e0
- 호커스: 테두리 색상 변경 (어두운 네이비)
- 모서리: 4-6px
- 패딩: 좌우 12px, 상하 10px
- 라벨: 입력창 위에 명확하게 (또는 플레이스홀더)

### 카드
- 배경: 흰색 또는 매우 밝은 회색
- 테두리: 선택 사항 (1px 연한 회색) 또는 그림자
- 모서리: 8px (과도한 둥글림 아님)
- 패딩: 16-24px
- 간격: 카드 간 16px
- 호버: 그림자 강화 (약간 들어올린 느낌)

### 배지 (상태)
- 높이: 24-28px
- 패딩: 좌우 8px, 상하 4px
- 모서리: 4px
- 폰트: 12-13px, 600 Weight

## 15. 메인 페이지 시각 효과 규칙

### 오로라 그라데이션 (Hero 배경)
- **색상**: 어두운 네이비 → 바이올렛 → 밝은 블루의 부드러운 다각형 그라데이션
- **효과**: 미세하고 세련되었으나 눈에 띄는 정도
- **성능**: CSS 그라데이션만 사용 (애니메이션 없음)

### 미세한 그리드 패턴
- **용도**: 배경 깊이감 (불필요한 시각 효과는 아님)
- **투명도**: 매우 약함 (배경 이미지 또는 SVG)
- **목표**: 배경이 살아있되, 글자 읽기에 방해 안 함

### 플로팅 카드 (질문/답변 예시)
- **위치**: Hero 영역 우측 또는 하단
- **스타일**: 흰색 카드, 그림자로 떠있는 느낌
- **내용**: "Q: 배송은 며칠 걸리나요?" / "A: 평균 3-5일입니다"
- **목표**: 실제 사용 예시를 동적으로 보여주기

### 애니메이션 제약
- **prefers-reduced-motion 준수**: 감소 설정 시 모든 애니메이션 비활성화
- **이동**: 스크롤 시 요소 진입 애니메이션은 최소화 (fade-in 정도만)
- **기간**: 애니메이션이 있으면 300-500ms (유휴하지 않게)

## 16. 로딩·빈 화면·오류·권한 없음 상태

### 로딩 상태
- **스피너**: 중앙에 회전하는 로고 또는 원형 진행 표시
- **스켈레톤**: 카드 목록에서는 회색 플레이스홀더 표시
- **시간**: 2초 이상 걸리면 진행 상태 표시

### 빈 화면 (Empty State)
```
[아이콘 또는 일러스트]

"아직 질문이 없습니다"

"첫 질문을 작성해보세요" (CTA 버튼)
```
- **배치**: 중앙 정렬, 여백 충분
- **아이콘 크기**: 64px
- **텍스트**: 제목 20px, 설명 14px
- **톤**: 긍정적이고 자연스러움

### 오류 상태
- **배너**: 빨간색 배경 + 흰색 텍스트
- **메시지**: 구체적 (예: "제목은 100자 이내여야 합니다")
- **아이콘**: 경고 아이콘 (△ 또는 !)
- **버튼**: "재시도" 또는 자동 2초 후 닫기

### 권한 없음 (403)
```
"이 질문에 접근할 수 없습니다"

"내 질문 목록으로" (링크)
```
- **배치**: 중앙, 큰 텍스트
- **색상**: 회색 또는 황색 배경
- **링크**: 명확한 네비게이션 옵션 제공

## 18. 접근성과 모션 감소 기준

### 키보드 네비게이션
- 모든 버튼과 링크는 Tab 키로 순회 가능
- 포커스 시각 표시 명확 (아웃라인 또는 배경색 변경)
- 포커스 트랩 없음 (ESC로 모달 닫기 등)

### 스크린 리더 지원
- 모든 이미지에 alt 텍스트 제공
- 폼 라벨이 명확하게 연결됨 (`<label for="id">`)
- ARIA 라이브 리전으로 동적 메시지 전달 (오류, 저장 완료 등)

### prefers-reduced-motion 준수
```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```
- 모든 애니메이션 비활성화
- 필수 기능은 즉시 표시 (진행 상태 없음)
