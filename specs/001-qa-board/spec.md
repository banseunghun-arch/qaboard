# QANOW: Question & Answer Community Platform

**Feature ID**: 001-qa-board  
**Version**: 1.0.0  
**Status**: Specification  
**Last Updated**: 2025-08-29

---

## Overview

QANOW는 사용자가 상품/서비스에 대한 질문을 남기면, 관리자가 답변하는 Q&A 게시판 플랫폼입니다. 회원과 관리자의 명확한 권한 분리, 직관적인 이용 흐름(질문 → 확인 → 답변 → 확인), MVP 중심의 단순한 구조를 목표로 합니다.

---

## Goals

1. **회원이 쉽게 질문할 수 있어야 한다**: 회원가입 후 몇 번의 클릭으로 질문 작성 완료
2. **회원이 질문 상태를 추적할 수 있어야 한다**: 자신의 질문 목록에서 "대기 중", "답변 완료" 상태 확인
3. **관리자가 효율적으로 답변할 수 있어야 한다**: 답변이 필요한 질문을 한눈에 찾아 답변 작성
4. **메인 페이지에서 서비스를 이해할 수 있어야 한다**: 질문 → 관리자 확인 → 답변의 이용 흐름이 시각적으로 명확

## User Personas & Scenarios

### Persona 1: 구매 전 질문을 하는 회원 (Member)

**Motivation**: 상품을 구매하기 전에 상세한 정보가 필요함  
**Scenario**:
- 메인 페이지에서 "질문 작성" CTA를 본 후 클릭
- 로그인 화면이 나타나면 계정으로 로그인
- 질문 제목과 내용을 작성하고 제출
- 질문 목록으로 이동하여 "답변 대기 중" 상태 확인
- 48시간 후 메일 알림을 받고, 질문 목록에서 관리자 답변을 확인
- 필요하면 답변을 보며 구매 결정

### Persona 2: 질문에 답변하는 관리자 (Admin)

**Motivation**: 고객 만족도를 높이기 위해 신속하고 정확한 답변 제공  
**Scenario**:
- 관리자 로그인
- "답변 필요" 필터로 미답변 질문 목록 확인 (5개 대기 중)
- 첫 번째 질문을 클릭하여 상세 내용 확인
- 답변 작성 폼에서 답변 텍스트 입력 및 저장
- 다음 질문으로 이동하여 반복
- 질문 목록으로 돌아가 "답변 완료" 상태로 변경된 것 확인

### Persona 3: 서비스를 처음 보는 비회원 (Guest)

**Motivation**: 서비스가 무엇인지, 어떻게 사용하는지 파악  
**Scenario**:
- 메인 페이지 방문
- "질문 작성 → 관리자 확인 → 답변 받기" 이용 흐름 시각 확인
- "빠른 답변", "신뢰할 수 있는 정보" 같은 가치 제안 읽음
- 흥미로워서 회원가입 버튼 클릭

## User Roles & Permissions

### Guest (비회원)

**Access**:
- 메인 페이지 조회 (서비스 소개, 이용 흐름)
- 질문 목록/상세 조회 **불가** (로그인 안내 표시)
- 질문 작성, 답변 조회 **불가**

**Actions**:
- 회원가입
- 로그인

### Member (회원)

**Access**:
- 메인 페이지 조회
- 자신의 질문 목록 조회
- 질문 상세 조회 (자신의 질문만)
- 관리자 답변 조회 (자신의 질문에 대한 답변만)
- 로그아웃

**Actions**:
- 질문 작성 (제목, 내용)
- 질문 수정 (답변 전에만)
- 질문 삭제 (답변 전에만)
- 답변 작성 **불가**

**Data Visibility**:
- 자신의 질문만 조회 가능
- 다른 회원의 질문, 답변 **불가**

### Admin (관리자)

**Access**:
- 메인 페이지 조회
- 모든 질문 목록 조회 (회원 관계없이)
- 질문 상세 조회 (모든 질문)
- 자신이 작성한 답변 조회/수정

**Actions**:
- 질문 상세 조회
- 답변 작성
- 답변 수정 (자신이 작성한 답변만)
- 질문 삭제 (부적절한 질문 제거, 회원의 삭제와 다른 권한)
- 로그아웃

**Data Visibility**:
- 모든 질문, 답변 조회 가능

## Core Features

### 1. Authentication & Authorization

#### Sign Up

**Triggers**: 회원이 "회원가입" 클릭

**Input**:
- Email: 유효한 이메일 형식
- Password: 최소 8자 (향후 정책 강화 가능)
- Name: 1-50자

**Output**: 계정 생성 후 메인 페이지로 리다이렉트, 로그인 상태 유지

**Validation**:
- Email 중복 확인
- 모든 필드 필수
- Password 최소 길이 검사

#### Login

**Triggers**: 비회원/로그아웃 상태에서 "로그인" 클릭 또는 보호된 페이지 접근

**Input**:
- Email
- Password

**Output**: 인증 성공 시 이전 페이지 또는 메인 페이지로 리다이렉트 + 세션 생성

**Validation**:
- 계정 존재 여부
- 비밀번호 일치 여부
- 실패 시 구체적 오류 메시지 없음 (보안: "이메일 또는 비밀번호가 일치하지 않습니다")

#### Logout

**Triggers**: 헤더의 "로그아웃" 클릭

**Output**: 세션 삭제, 메인 페이지로 리다이렉트

---

### 2. Question Management (질문 CRUD)

#### Create Question

**Triggers**: 회원이 "질문 작성" 버튼 클릭

**Input**:
- Title: 공백 제거 후 1-100자 (required)
- Content: 공백 제거 후 1-5000자 (required)

**Output**: 질문 저장, 질문 상세 페이지로 리다이렉트, "질문이 저장되었습니다" 메시지 표시

**Validation**:
- 클라이언트: 실시간 길이 체크 및 피드백
- 서버: 길이, 빈 입력, XSS 패턴 검사
- 실패 시 오류 메시지 표시 ("제목은 100자 이내여야 합니다")

**Status**: "답변 대기 중" (기본값)

#### Read Questions

##### 회원 시점: 자신의 질문 목록

**Triggers**: 로그인한 회원이 "내 질문" 또는 질문 목록 페이지 접근

**Output**: 자신의 질문 목록 (최신순), 각 질문에 대해:
- 제목
- 작성일
- 상태 ("답변 대기 중" / "답변 완료")

**Empty State**: 질문이 없으면 "아직 질문이 없습니다. 첫 질문을 작성해보세요." + "질문 작성" CTA

##### 관리자 시점: 모든 질문 목록

**Triggers**: 관리자가 질문 목록 페이지 접근

**Output**: 모든 회원의 질문 목록, 각 질문에 대해:
- 제목
- 작성자 (이메일 또는 이름)
- 작성일
- 상태 ("답변 대기 중" / "답변 완료")

**Filter** (MVP에 포함):
- "답변 필요" (상태 = "답변 대기 중")
- "답변 완료"

#### Read Question Detail

**Triggers**: 사용자가 목록에서 질문을 클릭

**Access Control**:
- 회원: 자신의 질문만 조회 가능 (다른 사용자 ID로 접근 시 "접근 권한이 없습니다" 메시지 + 404)
- 관리자: 모든 질문 조회 가능

**Output**: 질문 상세 정보
- 제목
- 내용
- 작성일, 작성자
- 상태
- 관리자 답변 (있으면 표시)
- 액션 버튼 (역할별 상이 - 아래 "Update/Delete" 참고)

#### Update Question

**Triggers**: 회원이 자신의 질문에서 "수정" 버튼 클릭

**Precondition**: 상태가 "답변 대기 중"이어야 함 (답변 완료 후 수정 불가)

**Input**: 제목, 내용 (유효성 규칙은 Create Question과 동일)

**Output**: 질문 수정 완료, 상세 페이지로 리다이렉트, "질문이 수정되었습니다" 메시지

**Access Control**: 자신의 질문만 수정 가능 (다른 사용자의 질문 수정 시도 시 403 "접근 권한이 없습니다")

#### Delete Question

**Triggers**: 
- 회원이 자신의 질문에서 "삭제" 버튼 클릭
- 관리자가 질문 상세 페이지에서 "삭제" 버튼 클릭 (부적절한 질문 제거)

**Precondition (회원)**: 상태가 "답변 대기 중"이어야 함 (답변 완료 후 삭제 불가)

**Precondition (관리자)**: 없음 (모든 질문 삭제 가능, 상태 제약 없음)

**Confirmation Dialog**: "이 질문을 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다."

**Output**: 질문 삭제, 목록 페이지로 리다이렉트, "질문이 삭제되었습니다" 메시지

**Access Control**:
- 회원: 자신의 질문만 삭제 가능 (답변 전)
- 관리자: 모든 질문 삭제 가능 (답변 여부 무관)

---

### 3. Answer Management (관리자 답변)

#### Create Answer

**Triggers**: 관리자가 미답변 질문의 상세 페이지에서 "답변 작성" 버튼 클릭

**Input**:
- Content: 공백 제거 후 1-5000자 (required)

**Output**: 답변 저장, 상태 "답변 완료"로 자동 변경, 상세 페이지에 답변 표시, "답변이 저장되었습니다" 메시지

**Validation**:
- 길이, 빈 입력, XSS 패턴 검사
- 중복 답변 방지 (이미 답변이 있으면 "이미 답변이 있습니다. 수정을 선택하세요")

**Post-Create Action** (향후):
- 회원에게 메일 알림 (현재 MVP에서 직접 확인만 가능, 메일은 추후 추가)

#### Update Answer

**Triggers**: 관리자가 자신이 작성한 답변에서 "수정" 버튼 클릭

**Input**: 답변 내용 (유효성 규칙은 Create Answer와 동일)

**Output**: 답변 수정 완료, 상세 페이지 새로고침, "답변이 수정되었습니다" 메시지

**Access Control**:
- 자신이 작성한 답변만 수정 가능
- 다른 관리자의 답변 수정 불가 (403 "접근 권한이 없습니다")

## Core Screens

### Screen 1: Main Page (메인 페이지)

**Purpose**: 서비스를 처음 보는 비회원에게 QANOW가 무엇인지, 어떻게 사용하는지 설득

**Layout & Content**:
1. **Header**: 로고, 네비게이션 (회원가입 / 로그인 또는 로그아웃)
2. **Hero**: 한 문장 서비스 소개 + "질문 작성" CTA
3. **Usage Flow Section**: 3단계 시각 (이미지/아이콘 + 텍스트)
   - Step 1: 사용자가 질문 작성
   - Step 2: 관리자가 질문 확인
   - Step 3: 사용자가 답변 확인
4. **Value Propositions**: 3-4개의 핵심 가치 (신뢰할 수 있는 답변, 빠른 응답 등)
5. **Footer**: 링크, 저작권

**Call-to-Action**:
- "지금 질문하기" (미인증 사용자는 로그인 페이지로 이동)

**State Handling**:
- 로드: 일반 화면 표시
- 로그인한 사용자: 헤더 "로그아웃" 표시

---

### Screen 2: Question List Page (질문 목록 페이지)

**Purpose**: 회원과 관리자가 질문 목록을 보고, 각자의 작업을 수행

**회원 시점**:

**Layout**:
1. **Header**: 로고, "내 질문" (활성), "로그아웃" 버튼
2. **Action Bar**: "새 질문 작성" 버튼
3. **List**:
   - 각 질문 카드: 제목, 작성일, 상태 ("답변 대기 중" / "답변 완료" - 텍스트 + 색상)
   - 클릭하면 상세 페이지로
   - 초기 로드: 최대 20개 항목 표시
4. **"더보기" 버튼**:
   - 목록 하단에 위치 (데이터가 20개 초과일 경우만 표시)
   - 클릭 시 다음 20개 항목 추가 로드
   - 진행 중: "로딩 중..." 상태 표시
5. **Empty State**: "아직 질문이 없습니다. 첫 질문을 작성해보세요." + "질문 작성" CTA

**관리자 시점**:

**Layout**:
1. **Header**: 로고, "질문 목록" (또는 관리자 대시보드), "로그아웃" 버튼
2. **Filter Bar**:
   - "전체" (기본)
   - "답변 필요" (상태 = "답변 대기 중")
   - "답변 완료"
3. **List**:
   - 각 질문 카드: 제목, 작성자, 작성일, 상태
   - 클릭하면 상세 페이지로
   - 초기 로드: 최대 20개 항목 표시
4. **"더보기" 버튼**: 회원 시점과 동일
5. **Empty State**: "아직 질문이 없습니다."

**Common Behavior**:
- 모바일 네비게이션: 상단 고정 헤더 + 뒤로가기/링크로만 구성
- 새로고침은 필요시 브라우저 기본 새로고침 사용

---

### Screen 3: Question Detail Page (질문 상세 페이지)

**Purpose**: 질문 및 답변을 확인, 작성, 수정, 삭제

**회원 시점**:

**Access Control**:
- 자신의 질문만 조회 가능
- 다른 회원의 질문에 접근 시: HTTP 403 + "이 질문에 접근할 수 없습니다" 메시지 + "내 질문 목록으로" 링크

**Layout**:
1. **Header**: 로고, "내 질문" 링크, "로그아웃"
2. **Breadcrumb 또는 "내 질문으로" 링크**: 상단 또는 하단에 위치
3. **Question Card**:
   - 제목
   - 작성일, 상태 ("답변 대기 중" / "답변 완료" - 텍스트 + 색상)
   - 내용
   - 액션 버튼 (상태에 따라):
     - 답변 대기 중: "수정" 버튼, "삭제" 버튼
     - 답변 완료: 버튼 없음 (읽기 전용)
4. **Answer Section** (조건부):
   - 답변이 있으면: 관리자 답변 내용 표시
   - 답변이 없으면: "아직 답변이 없습니다. 잠시만 기다려주세요." 메시지
5. **Form Pattern** (폼 표시 시):
   - 폼 제목: "질문 수정" (또는 "질문 작성")
   - 필드: 텍스트 에어리어 (제목 또는 내용)
   - 버튼: "저장" / "취소"
   - 에러 메시지: 하단 또는 필드 위에 표시
   - 진행 상태: "저장 중..." 표시

**관리자 시점**:

**Access Control**:
- 모든 질문 조회 가능

**Layout**:
1. **Header**: 로고, "질문 목록" 링크, "로그아웃"
2. **Breadcrumb 또는 "질문 목록으로" 링크**: 상단 또는 하단에 위치
3. **Question Card**:
   - 제목
   - 작성일, 작성자, 상태
   - 내용
   - 액션 버튼:
     - "삭제" 버튼 (항상 표시, 상태 무관, 부적절한 질문 제거용)
4. **Answer Section** (조건부):
   - 답변이 없으면:
     - "답변 작성" 버튼
     - 클릭하면 폼 표시 (텍스트 에어리어 + "저장" / "취소")
   - 답변이 있으면:
     - 관리자 답변 내용 표시 (작성일)
     - "수정" 버튼 (자신이 작성한 답변만)
     - 클릭하면 폼으로 전환
5. **Form Pattern** (폼 표시 시):
   - 폼 제목: "답변 작성" 또는 "답변 수정"
   - 필드: 텍스트 에어리어 (답변 내용)
   - 버튼: "저장" / "취소"
   - 에러 메시지: 하단 또는 필드 위에 표시
   - 진행 상태: "저장 중..." 표시

## Input Validation Rules

### Question Title
- **Min Length**: 1 (공백 제거 후)
- **Max Length**: 100 (공백 제거 후)

- **Error Messages**:
  - "제목은 필수입니다"
  - "제목은 100자 이내여야 합니다"
  - "제목에 포함될 수 없는 문자가 있습니다"

### Question Content
- **Min Length**: 1 (공백 제거 후)
- **Max Length**: 5000 (공백 제거 후)
- **Character**: 일반 텍스트 + 줄바꿈 허용 (XSS 패턴 필터링)
- **Error Messages**:
  - "내용은 필수입니다"
  - "내용은 5000자 이내여야 합니다"
  - "내용에 포함될 수 없는 문자가 있습니다"

### Answer Content
- **Min Length**: 1 (공백 제거 후)
- **Max Length**: 5000 (공백 제거 후)
- **Character**: 일반 텍스트 + 줄바꿈 허용 (XSS 패턴 필터링)
- **Error Messages**:
  - "답변은 필수입니다"
  - "답변은 5000자 이내여야 합니다"
  - "답변에 포함될 수 없는 문자가 있습니다"

### Email (Sign Up)
- **Format**: RFC 5322 (또는 간단한 이메일 정규식)
- **Max Length**: 254자 (RFC 표준)
- **Duplicate Check**: 데이터베이스에서 중복 확인
- **Error Messages**:
  - "유효한 이메일 주소를 입력하세요"

### Name (Sign Up)
- **Min Length**: 1
- **Max Length**: 50
- **Character**: 일반 텍스트
- **Error Messages**:
  - "이름은 필수입니다"
  - "이름은 50자 이내여야 합니다"

## Security & Access Control

### Authentication
- 회원가입/로그인: 비밀번호 해싱 (bcrypt 또는 유사)
- 세션: 서버 세션 (또는 JWT, 기술 스택 결정 후)
- HTTPS: 모든 통신 암호화

### Authorization (Data Layer)
- API 핸들러: 모든 요청에 사용자 인증 확인
- 데이터베이스 쿼리: WHERE 절에 사용자/역할 필터 추가
  - 회원: `WHERE question.created_by = current_user_id`
  - 관리자: 전체 데이터 접근
- 거부 시: 401 (미인증) 또는 403 (미인가) HTTP 상태 반환

### Input Validation
- 클라이언트: 즉시 피드백 (길이, 빈 입력)
- 서버: 모든 입력 재검증 + XSS 패턴 필터링

### Session & Logout
- Logout 시: 세션 삭제, 쿠키 제거
- 세션 타임아웃: 설정 가능 (예: 24시간)

## Assumptions

1. **Email-based Authentication**: 회원가입/로그인은 이메일과 비밀번호 기반 (소셜 로그인 MVP 제외)
2. **Server-side Session**: 세션은 서버에서 관리 (또는 JWT, 기술 스택 결정 후)
3. **Timezone**: 현재 모든 시간 표시는 서버 타임존 기준 (향후 사용자 타임존 지원 가능)
4. **Real-time Notification**: 관리자가 답변하면 회원은 메일이나 인앱 알림을 받음 (현재 MVP에서는 회원이 직접 확인, 메일 알림은 추후 추가)
5. **Moderation**: 관리자는 부적절한 질문/답변을 수정/삭제할 수 있음 (현재 명세에는 상세히 정의되지 않음)
6. **Mobile Design**: 모든 화면은 모바일-우선 반응형 디자인 적용

  And 질문 목록에 새 질문이 보임

**Implication**: FAQ는 향후 Phase 2에서 추가 가능 (고객 질문이 충분히 수집된 후)

### ✅ Q2: 미인증 사용자의 "질문 작성" CTA

**Decision**: **A - 로그인 페이지로 이동**  
**Rationale**: 기존 사용자 우선, 로그인이 회원가입보다 먼저 노출되어 사용 편의성 향상  
**Implication**: 로그인 페이지에서 "회원가입" 링크 제공으로 신규 사용자도 쉽게 가입 가능

### ✅ Q3: 관리자의 질문 삭제 권한

**Decision**: **B - 삭제만 가능 (수정은 불가)**  
**Rationale**: 부적절한 질문은 삭제하여 제거, 수정은 불가능하여 원본 보존 및 감시 추적 용이  
**Implication**: 
- 관리자는 Delete Question 권한만 보유
- 관리자는 질문 내용을 수정할 수 없음 (회원이 의도한 원본 유지)
- 부적절한 질문은 삭제로 대응 (답변 여부 무관, 모든 상태에서 삭제 가능)

### ✅ Q4: 권한 없는 URL 접근 시 처리

**Decision**: **B - 403 Forbidden + "이 질문에 접근할 수 없습니다" 메시지 + 목록 링크**  
**Rationale**: 사용자가 왜 접근할 수 없는지 명확히 이해하고, 빠르게 목록으로 돌아갈 수 있도록 안내  
**Implication**:
- HTTP 상태: 403 (Forbidden)
- 메시지: "이 질문에 접근할 수 없습니다"
- 액션: "내 질문 목록으로" 또는 "목록으로" 링크
- 보안: 존재하지 않는 것처럼 보이지 않음 (권한 문제임을 명시)

### ✅ Q5: 모바일 네비게이션 구조

**Decision**: **A - 상단 고정 헤더 + 뒤로가기 버튼**  
**Rationale**: 웹 표준 패턴으로 가장 단순하고 모든 디바이스에서 일관된 UX 제공  
**Implication**:
- 상단 고정 헤더: 로고 + 로그아웃 버튼만
- 페이지 간 이동: 뒤로가기 + 명시적 링크 (예: "내 질문으로", "목록으로")
- 하단 탭바/햄버거 메뉴 없음
- 모바일(375px) ~ 데스크톱(1440px)에서 일관된 네비게이션

### ✅ Q6: 화면 패턴 일관성 - 폼 구조

**Decision**: **A - 모든 폼이 동일한 레이아웃 사용**  
**Rationale**: 일관된 패턴으로 사용자 학습 최소화 및 컴포넌트 재사용으로 개발 효율성 증가  
**Implication**:
- 질문 작성, 질문 수정, 관리자 답변 폼 모두 동일 구조
- 폼 구성: 제목(선택) + 콘텐츠 텍스트에어리어 + 저장/취소 버튼 + 에러 메시지 + 진행 상태
- 헌법 원칙 V (UI Consistency) 준수

### ✅ Q7: 목록 로드 방식

**Decision**: **B - 초기 20개 로드 + "더보기" 버튼으로 추가 로드**  
**Rationale**: MVP 원칙 준수, 성능 목표(LCP < 2.5초) 달성, 명확한 UX 제공  
**Implication**:
- 초기 로드: 최대 20개 항목만 표시
- "더보기" 버튼 클릭 시 다음 20개 추가
- 페이지네이션 없음 (MVP 제외)
- 무한 스크롤 없음 (성능 추적 어려움)
- 접근성: 버튼 클릭으로 명확한 제어 가능

### ✅ Q8: 로그인 후 리다이렉트

**Decision**: **A - 메인 페이지로 이동**  
**Rationale**: 폼 데이터 임시 저장 기능이 없으므로, 간단한 흐름으로 사용자가 다시 시작하도록 유도  
**Implication**:
- 로그인 성공 → 메인 페이지로 이동
- 사용자가 다시 "질문 작성" 클릭하여 새로운 폼 시작
- 폼 데이터 보존 기능 불필요 (MVP)
- 세션 관리 간단 (무상태 설계)
